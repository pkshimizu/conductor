# conductor

要件（GitHub Issue）を渡すと、テスト役・実装役・レビュー役の Claude Code を順に動かし、CI を通してマージまで進める開発エージェント。

開発中（Lv1）。

## 動かし方

```
conductor check [フォルダ]   設定を点検する
conductor start [フォルダ]   常駐して Issue を進める
```

- 90 秒ごとに GitHub Project を確かめ、作業中の Issue を1段階進めます。作業中の Issue が無ければ Ready 列から番号の小さいものを1件拾います。
- 作業中に数えるのは1件だけです。承認待ちの Issue は数えず、毎回 PR のコメントだけを確かめます。
- PR が main と衝突したら、実装役に差し戻して直させます（差し戻しの上限には数えません）。
- 同じ Issue が3回続けて失敗したら Blocked 列に移し、`github.notify` の人をメンションします。
- Ctrl+C を受けたら、今の段階を終えてから止まります。
- 進み具合の記録は `~/.conductor/state/<owner>__<repo>.db` に置きます。止めて再開しても続きから進みます。

## 対象リポジトリに置くもの

```
.conductor/
  config.yaml        設定
  tester/*.md        テスト観点（テスト役が参照する）
  implementer/*.md   実装ルール（実装役が参照する）
  reviewer/*.md      レビュー観点（1ファイルにつき1人のレビュー役が並列で確認する）
```

- 各フォルダの .md はファイル名の順に読みます。フォルダが無ければ追加の指示なしで動きます。
- レビュー役は観点ごとに並列で動き、1つでも差し戻しなら差し戻し、異議があれば異議、全員が承認ならマージします。
- 同時に動かすレビュー役の数は `limits.reviewers`（既定 3）で決めます。
- 役が書く文章（要約・指摘・質問）の言語は `language`（既定 `日本語`）で決めます。例: `language: English`。conductor が書く定型文は日本語のままです。

## マージの承認

```yaml
merge:
  approval: human # human（既定）または auto
```

- `human`：レビュー役が承認したら PR でメンションして待ちます。書き込み権限のある人が PR に `/conductor approve` とコメントするとマージします。
- `/conductor reject`：承認待ちになった後のコメント（行へのコメントを含む）を指摘として実装役に差し戻します。差し戻しの上限回数には数えません。
- `auto`：人の確認なしに、レビュー役が承認したらすぐマージします。
