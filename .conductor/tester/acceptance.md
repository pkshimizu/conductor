- 受け入れテストは `src/acceptance/` に Vitest で書く。ファイル名は `src/acceptance/<Issue番号>-<機能>.test.ts`（例：`src/acceptance/38-chat-config.test.ts`）。
- 1つの AC につき 1つの `it`（または `test`）にする。テスト名は `AC1: ...` のように AC の番号から始める。
- まだ無いモジュールや関数を使ってよい。そのときは置き場所と名前を決めて import する（例：`../chat.js`）。実装役はテストが使う名前と型に合わせて作る。既にあるモジュール（`src/config.ts`・`src/store.ts` など）に足す方が自然なら、そちらから import する。
- import は `.js` 拡張子を付ける（NodeNext）。
- 外部（Discord・GitHub・claude・SQLite のファイル）には触らない。窓口・GitHub・claude はテスト用の偽物に差し替え、SQLite はメモリ上の記録（`MemoryStore` など）か一時フォルダを使う。ネットワークに出るテストは書かない。
- 時刻や待ち時間に頼らない。待ちが要るときは偽のタイマーか、確認を1回ずつ呼ぶ形にする。
- テストは中身の作りではなく、外から見える振る舞い（返り値・偽物に残った呼び出し・書き込まれた文）で確かめる。
- アプリのコード（`src/` の `src/acceptance/` 以外）は書かない。まだ無いモジュールのテストが失敗するのは正しい状態。
- 既存のテストは消さない・変えない。
