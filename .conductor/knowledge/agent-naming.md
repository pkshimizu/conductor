# 方針「エージェントの呼び名」

conductor が動かす Claude Code の各役（と conductor 自身）を、人に見せる文章でどう呼ぶかの決まり。

## 呼び名

人に見せる文章では「～役」と書かず、「～エージェント」と書く。

| 中のキー（`ActiveRole` など） | 人に見せる呼び名 |
| --- | --- |
| `tester` | テストエージェント |
| `implementer` | 実装エージェント |
| `reviewer` | レビューエージェント |
| `specifier` | 仕様化エージェント |
| `decomposer` | 分解エージェント |
| （conductor 自身） | 指揮エージェント |

- 「役」だけを単独で使っている文言（「役ごとの追加許可」「役の許可」「役」の見出しなど）も「エージェント」にする（「エージェントごとの追加許可」など）。
- `ci`・`merge` は役ではないので今の呼び名（「CI」「CI の確認」「マージ」）のまま。

## 人に見せる文章とは

- GitHub の Issue・PR に書く本文とコメント
- Discord に書く書き込み
- 管理画面（`web/src/i18n.ts` の日本語の文言）
- 標準出力・ログ・エラーの文言
- README.md

## 変えないもの

- `claude -p` に渡すだけの文章（各役の決まり `*_RULES`、役への依頼文や指摘の前置き）。人には見せないため。
- コードの識別子・設定のキー・ファイルの置き場所（`roles`・`ActiveRole`・`.conductor/<役>/` など）。互換を保つため。
- コードのコメント。
- 英語の文言（`Tester`・`role` など）。「～役」に当たる書き方ではないため。

## 書き方

- 同じ呼び名を複数の場所で使うときは、1か所の辞書（`src/loop.ts` の `ROLE_LABELS`、`web/src/i18n.ts` の `roles`）から引く。新しく呼び名を手で書くときも上の表に合わせる。
